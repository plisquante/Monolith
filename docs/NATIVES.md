## What this means

* Every native the program calls is implemented in Rust. Nothing is missing; the generated program stops loudly for any that is not.
* "Rust-native" is not the same as "no JNI/JNA": the JNA and Netty natives are Rust code that *emulates* a JNI/libffi library
  so that unchanged Java classes (JNA, Netty) run. Removing them means removing the Java callers, not the Rust functions.
* **Netty (174):** Netty chooses epoll/kqueue when they are available. Setting `io.netty.transport.noNative=true` makes it
  use the NIO transport (plain Java, no native code). The runtime now sets this default (`monolith/rt/rt.rs` `user_props`).
  Check: `monolith/netty_tests.py` (HotSpot and Rust agree on `Epoll.isAvailable()`). This removes the epoll/kqueue natives
  from the hot path; the 174 functions stay in the tree until no generated code references them (next regeneration).
* **JNA (56):** all in `com.sun.jna.Native`. The callers are oshi (system info), the narrator and similar. Plan: a Rust patch
  that answers those callers directly (oshi: system properties), or the removal of the optional features. To do: find the callers.
* **JDK (556) and graphics/audio (162):** these are the native surface of the runtime itself; they stay Rust. The Java
  overlays (`classlib/`, `runtime/java_nolwjgl/`) are the Java part that remains (WS7).
